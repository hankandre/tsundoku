# Bun API EPUB Auto-Discovery + E2E Plan

## Goal
Implement Java-like discovery flow in `apps/tsundoku-api` (manual trigger, task-backed execution, event-driven file detection), then add end-to-end tests that use the root fixture:

- `Seneca - On the Shortness of Life (2004).epub`

## Recommended Approach

1. Build a minimal but real discovery pipeline first (filesystem scan -> EPUB metadata extraction -> DB persistence) and wire it into existing task infrastructure.
2. Expose parity entry points:
   - `PUT /api/v1/libraries/:libraryId/refresh` (currently `501`) for manual per-library rescan.
   - Existing `POST /api/v1/tasks/start` for `SCAN_LIBRARY` and `SCAN_FILES` should execute real runners.
   - File change events should trigger targeted discovery jobs for changed files/paths.
3. Keep a low-frequency reconciliation scan as a safety net (for missed fs events, restarts, network mounts).
4. Validate with e2e tests that import the project-root EPUB through the new scan flow and assert persisted book + metadata.

## Implementation Plan

### 1) Discovery core (library scan)
- Add a library scanning service that:
  - Reads `library_path` entries for a library.
  - Recursively walks folders.
  - Filters supported book formats (start with `epub`, keep extension list centralized for easy parity expansion).
  - Skips hidden/temp files and non-files.
  - Upserts/creates book records only when file is not already present for that library.
- Persist to existing tables in one transaction per file (or per batch):
  - `books`
  - `book_file`
  - `book_metadata` (+ author mappings when available)

### 2) EPUB metadata extraction
- Add a focused EPUB parser utility:
  - Open archive, resolve `META-INF/container.xml`, then OPF.
  - Extract at least: title, subtitle (if present), author(s), language, publisher, published date, ISBN 10/13.
  - Return normalized metadata shape used by discovery service.
- Keep extraction readable and small (no non-null assertions, clear variable names, graceful fallback when fields are missing).

### 3) Task execution parity
- Extend task layer so created tasks can run instead of only storing `PENDING` rows:
  - `SCAN_LIBRARY`: run library rescan for one/all libraries based on task options.
  - `SCAN_FILES`: run bookdrop folder scan (for parity with Java periodic bookdrop scanning).
- Add a task runner/orchestrator service that updates:
  - `status` (`PENDING` -> `RUNNING` -> `COMPLETED`/`FAILED`/`CANCELLED`)
  - `progressPercentage`, `message`, `errorDetails`, `completedAt`.

### 4) Event-driven execution (watch parity)
- Add app-level watcher bootstrap that:
  - Creates file watchers for each configured `library_path` (and bookdrop path when enabled).
  - Reacts to `create` and `rename/move` style events by enqueueing targeted scan tasks.
  - Debounces burst events and coalesces duplicate paths.
- Add startup reconciliation behavior:
  - On app boot, run a one-time reconciliation scan for watched libraries.
  - Keep optional low-frequency periodic reconciliation (not primary trigger).
- Keep execution in-process for now (single-node assumption in dev/test).

### 5) Route updates
- Implement `PUT /api/v1/libraries/:libraryId/refresh` in `libraries.ts`:
  - Validate access.
  - Enqueue/start `SCAN_LIBRARY` task for the target library.
  - Return accepted payload with task id/status.
- Keep existing `POST /api/v1/tasks/start` contract; just ensure `SCAN_LIBRARY` and `SCAN_FILES` now execute.

### 6) E2E tests with root EPUB fixture
- Add e2e test file(s) that use `app.request` and real DB-backed flow.
- Test setup:
  - Create a temporary library directory.
  - Copy `Seneca - On the Shortness of Life (2004).epub` into that directory.
  - Create admin user/session through existing public setup/auth routes.
  - Create library pointing to temp path.
- Assertions:
  - Calling refresh/task start returns accepted/success state.
  - At least one `books` row is created for that library.
  - `book_metadata` contains extracted title/author fields (non-empty and fixture-consistent).
  - Re-running scan does not duplicate the same file entry.
- Teardown:
  - Remove created DB rows and temporary filesystem artifacts.

## Event-Based Notes

- Yes, this can be done in Bun API with filesystem watchers (`fs.watch`-style behavior in Bun runtime).
- Recommended architecture is hybrid event-first:
  - Primary trigger: file events (`add`, `rename/move`) -> enqueue targeted discovery task.
  - Reliability fallback: startup reconciliation + optional slow interval full scan.
- This avoids cron as the main driver while still handling missed notifications on some filesystems.
